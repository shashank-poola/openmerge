# Agents & Rules

OpenMerge runs three specialist agents in parallel. OpenMerge then grounds and verifies each candidate before publication.

Agents report confirmed defects in changed code. OpenMerge suppresses uncertain findings, style-only advice, and unsupported hypotheses.

## Code Quality Agent

Checks for correctness and reliability regressions introduced by the change.

- Detects broken control flow and incorrect state transitions
- Detects changed behavior that violates a supported contract
- Reports missing error handling at boundaries

## Security Agent

Scans for demonstrated attack paths, exposed secrets, and OWASP top 10 patterns.

- SQL injection, XSS, and command injection vectors
- Hardcoded secrets and API keys
- Insecure direct object references

## Performance Agent

Identifies N+1 queries, unnecessary allocations, and algorithmic complexity issues.

- Database N+1 query patterns
- Unnecessary re-renders in React components
- O(n²) loops that can be optimized

## Finding Verifier

The verifier challenges every grounded candidate before OpenMerge publishes it.

- Requires an exact changed-file and added-line anchor
- Checks the claim against bounded diff and source evidence
- Suppresses speculative or unsupported findings
- Can lower severity but cannot increase it
- Cannot add a finding or move its location

OpenMerge treats LOW as a confirmed minor defect, not a low-confidence concern. Only verified HIGH and CRITICAL findings block a merge.
